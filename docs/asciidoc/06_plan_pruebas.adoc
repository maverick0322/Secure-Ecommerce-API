=== Reporte de 3 Pruebas de Penetración con Metasploit
Se planifican y documentan pruebas de penetración ofensivas contra la superficie expuesta de la API:

1. **Prueba 1: Escaneo de Vulnerabilidades HTTP (`auxiliary/scanner/http/http_version`):**
* *Objetivo:* Identificar versión de Express y posibles vulnerabilidades de divulgación de tecnología.
* *Resultado:* Mitigado. La cabecera `X-Powered-By` está deshabilitada y la API responde con cabeceras genéricas.
2. **Prueba 2: Fuerza Bruta sobre Endpoint de Login (`auxiliary/scanner/http/http_login`):**
* *Objetivo:* Evaluar la resistencia del endpoint `POST /api/auth` ante ataques de diccionario.
* *Resultado:* Mitigado. Las respuestas son idénticas en tiempo y mensaje ante usuarios inexistentes o contraseñas inválidas (*Timing Attack resistant*).
3. **Prueba 3: Intento de Carga de Payload Shell (`exploit/multi/http/...`):**
* *Objetivo:* Enviar una reverse shell PHP/ELF simulada a través de `POST /api/archivos`.
* *Resultado:* Rechazado inmediatamente con `400 Bad Request` por validación de firma mágica y tipo MIME de Multer.

=== Pruebas de Inyección SQL (CWE-89)
* **Vector Evaluado:** Parámetros en URLs y campos de búsqueda (`/api/productos?s=' OR '1'='1`).
* **Mecanismo Defensivo:** Adopción de Sequelize ORM con sentencias preparadas nativas.
* **Resultado:** La búsqueda trata el parámetro como una cadena de caracteres literal escapada (`%\\' OR \\'1\\'=\\'1%`), neutralizando cualquier intento de alteración sintáctica.

=== Pruebas de Estrés y Rendimiento (CWE-400)
* **Objetivo:** Verificar la estabilidad de la API ante ráfagas concurrentes de peticiones sobre consultas relacionales pesadas.
* **Herramienta:** Apache Benchmark (`ab`) / Autocannon.
* **Resultado:** La API procesa peticiones concurrentes manteniendo un uso de CPU y memoria controlado dentro del contenedor Docker sin fugas de memoria (*memory leaks*).

=== Pruebas contra Falsificación de Peticiones en Sitios Cruzados (CSRF)
* **Evaluación:** Dado que la API opera bajo una arquitectura **100% sin estado (stateless)** mediante tokens JWT transmitidos en la cabecera `Authorization: Bearer <token>` y no utiliza cookies de sesión automáticas, el vector de ataque clásico de CSRF queda **completamente neutralizado por diseño arquitectónico**.

=== Pruebas contra Cross-Site Scripting (XSS - CWE-79)
* **Evaluación:** La API solo intercambia datos mediante serialización estricta `application/json`.
* **Sanitización:** Los valores de entrada son procesados por `express-validator` suprimiendo caracteres de escape y evitando su interpretación como código HTML ejecutable.
